# 01. 디자인 시스템 기초

## 디자인 시스템이 뭔가요?

한마디로: "이 프로젝트에서 쓸 색, 글자 크기, 여백을 미리 정해둔 규칙집"입니다.

규칙집이 없으면 무슨 일이 생기냐면 —
화면마다 버튼 색이 조금씩 다르고, 어떤 제목은 20px인데 다른 화면 제목은 22px이고,
여백도 화면마다 들쭉날쭉해져서 "같은 앱인데 통일감이 없다"는 느낌을 줍니다.
담당표에 있는 "전체 화면 일관된 스타일"이 바로 이걸 막기 위한 겁니다.

규칙을 먼저 정해두면, 나중에 화면을 10개를 만들든 20개를 만들든
그 규칙 안에서만 고르면 되니까 오히려 더 빨리 만들 수 있습니다.

---

## 1. 색상 팔레트 (Color Palette)

색은 아무렇게나 여러 개 쓰는 게 아니라, 역할을 정해서 소수의 색만 씁니다.

| 역할 | 설명 | 예시 |
|---|---|---|
| Primary(주 색상) | 브랜드를 대표하는 색. 버튼, 강조 요소에 사용 | 타비도리라면 여행 느낌의 청록/오렌지 계열 |
| Secondary(보조 색상) | Primary를 보완하는 색. 자주 쓰진 않음 | Primary와 대비되는 색 |
| Neutral(무채색) | 배경, 글자, 테두리에 쓰는 흰색~회색~검정 단계 | #ffffff ~ #1a1a1a |
| Semantic(의미 색상) | 성공/경고/에러처럼 "의미"를 전달하는 색 | 성공=초록, 에러=빨강, 경고=노랑 |

**포인트**: Primary 색은 보통 1개만 정합니다. 색이 많아질수록 화면이 산만해집니다.
타비도리처럼 "검증 결과 통과/실패", "일정 하이라이트" 같은 상태 표시가 있는 프로젝트는
Semantic 색상(성공/실패/경고)을 미리 정해두는 게 특히 중요합니다 — 담당표에 있는
"패턴칩 표시", "병목 하이라이트" 기능이 결국 이 Semantic 색상을 쓰게 됩니다.

## 2. 타이포그래피 스케일 (Typography Scale)

글자 크기도 아무 숫자나 쓰지 않고, 몇 단계만 정해서 반복해서 씁니다.
많이 쓰는 방식은 "1.25배씩 커지는" 식으로 단계를 만드는 겁니다.

| 단계 | 크기(예시) | 용도 |
|---|---|---|
| Heading 1 | 32px | 페이지 제목 |
| Heading 2 | 24px | 섹션 제목 |
| Heading 3 | 20px | 카드/블록 제목 |
| Body | 16px | 본문, 설명 |
| Caption | 13px | 부가 설명, 라벨 |

폰트 굵기(font-weight)도 보통 2~3단계만 씁니다: Regular(400), Medium(500), Bold(700).

---

## 3. 여백 규칙 (Spacing System)

여백(padding, margin, gap)을 "4의 배수"로만 쓰는 규칙이 실무에서 제일 흔합니다.
예: 4px, 8px, 12px, 16px, 24px, 32px, 48px

이렇게 하면 "이 여백은 8px일까 10px일까" 매번 고민할 필요가 없어지고,
화면들끼리 여백 느낌이 자연스럽게 맞아떨어집니다.
